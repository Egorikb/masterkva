Perplexity prompt для MasterKva

Ты анализируешь проект MasterKva — платформу обучения математике для 1–9 классов.

Важно:
- не переписывай мой бриф своими словами;
- не делай generic summary;
- дай конкретные рекомендации, где можно улучшить архитектуру, логику, данные и UX;
- если видишь, что какой-то подход стоит упростить, скажи это прямо;
- отвечай по-русски.

## Контекст проекта
MasterKva — это платформа, где ученик проходит:
- диагностику;
- выявление слабых тем;
- объяснение по теме;
- практику;
- проверку закрепления;
- переход дальше по программе.

В проекте есть учебные материалы, визуальные шаблоны и интерактивная доска. Для ранней арифметики особенно важен `number_bond`, а не общий CPA-шаблон.

## Что уже не идеально
- текущий диагностический пул слишком маленький для полной диагностики всей программы
- нужен более строгий механизм выбора следующего вопроса
- нужен понятный цикл: ошибка -> похожие задачи -> проверка -> слабая тема -> обучение
- нужны более чёткие правила включения и выключения доски по фазам
- нужна более надёжная структура данных для навыков и тем

## Что я хочу от тебя
1. Дай критичный разбор текущей архитектуры.
2. Скажи, что стоит упростить в первой версии.
3. Предложи, какие данные и сущности нужно хранить.
4. Опиши лучший механизм выбора следующего вопроса.
5. Опиши лучший loop после ошибки ученика.
6. Назови 3–5 наиболее вероятных failure modes в реальном использовании.
7. Предложи 3–5 конкретных улучшений, которые дадут максимальный эффект.
8. Если у тебя есть альтернативная архитектурная идея, предложи её.

## Формат ответа
- сначала краткий вывод;
- затем список проблем и улучшений;
- затем конкретные рекомендации по архитектуре;
- затем риски и edge cases;
- без воды и без повторения исходного описания.

Если уместно, можешь дополнительно дать:
- минимальную схему данных;
- rule-based selection strategy;
- remediation loop;
- staged rollout plan.

Сфокусируйся на практических улучшениях, которые реально можно внедрить в MasterKva.
