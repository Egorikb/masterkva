# Действия Panda Chat

Контракт B2a/B2b для `POST /api/v1/plugins/panda/chat`. Сервер хранит фазу, текущую часть и число попыток; клиент отправляет намерение ребёнка и не назначает следующий шаг сам.

## Запрос

```json
{
  "user_id": "child-1",
  "message": "12",
  "mode": "curricular",
  "lesson_id": "g1-t12-l01",
  "content_version": "2.0",
  "action": "answer",
  "request_id": "018f-answer-0001",
  "session_id": "b09a5704-8e69-4cf7-a240-6ac1d87a6657",
  "part_revision": 0
}
```

`action` принимает `start`, `answer`, `hint`, `rephrase`, `pause`, `resume`, `advance` или `null`. Поля `mode`, `lesson_id` и `content_version` нужны для запуска curricular-урока и проверки, что запрос относится к сохранённой сессии. `message` обязателен, но для кнопок `start`, `hint`, `rephrase`, `pause`, `resume` и `advance` может быть пустой строкой.

## Идемпотентность B2b

- `request_id` — созданный клиентом непустой идентификатор длиной до 128 символов. Новый ID нужен для каждого нового намерения ребёнка.
- `session_id` выдаёт сервер в `state.session_id` после `start`. В первый `start` его не передают; во все последующие запросы занятия Terra передаёт полученное значение.
- `part_revision` выдаёт сервер в `state.curricular.part_revision`. Значение начинается с `0` и увеличивается только после принятого `advance`.

Область уникальности `request_id` — ребёнок (`user_id`) и `session_id`. Повтор той же тройки с тем же содержимым возвращает сохранённый ответ с `replayed: true`. Он не создаёт попытку и не повторяет переход. Тот же ID с другим сообщением или действием возвращает `request_id_conflict`. Новый ID с тем же ответом является новой попыткой, пока часть активна.

Повтор `start` с тем же ID не создаёт новое занятие. Повтор принятого `advance` не перепрыгивает ещё одну часть. Сначала сервер ищет сохранённый результат, затем проверяет позицию: поэтому повтор уже принятого ответа можно безопасно получить после перехода, а новый ответ со старым `part_revision` возвращает `stale_part`.

При наличии `request_id` ответ содержит:

```json
{
  "request_id": "018f-answer-0001",
  "replayed": false,
  "event_kind": "math_attempt"
}
```

`event_kind` принимает `math_attempt`, `help_request`, `technical_event`, `unparsed_input` или `manual_review`. Пустой/неразобранный ответ получает `unparsed_input`, не увеличивает математические или неправильные попытки и не подтверждает пробел навыка.

## Семантика действий

| Действие | Допустимое состояние | Результат |
|---|---|---|
| `start` | `mode=curricular`, разрешённые `lesson_id` и `content_version` | Сервер создаёт или перезапускает curricular-сессию с первой части. |
| `answer` | Текущий вопрос в `curricular`, `diagnostic`, `practice` или `remediation` | Только разобранный ответ записывает математическую попытку. Сервер решает, завершена ли часть и какой переход разрешён. |
| `hint` | Незавершённая текущая часть или текущий legacy-вопрос | Возвращает подсказку без оценки сообщения, новой попытки и перехода. |
| `rephrase` | Незавершённая текущая часть или текущий legacy-вопрос | Возвращает тот же вопрос другими словами, сохраняя числа и математический смысл; сообщение не оценивается. |
| `pause` | Активная учебная фаза | Сохраняет фазу, урок, версию и текущую часть; сообщение не оценивается. |
| `resume` | `phase=paused` | Возвращает сохранённый вопрос; содержимое `message` не считается ответом. |
| `advance` | Curricular-часть, которую сервер уже отметил завершённой | Переходит ровно к следующей части. До завершения возвращает ошибку. Завершённый урок остаётся завершённым. |

После `hint` и `rephrase` UI сохраняет прежнее поле ввода или очищает его по своему правилу, но не отправляет текст повторно как `answer` без нового действия ребёнка. Ответы помощи не содержат серверных `answer`, `expected` или следующей части. Предыдущий `practice_feedback` может остаться в состоянии как история последней математической попытки; помощь не создаёт новый feedback.

`state.curricular.incorrect_attempts` считает только ответы со статусом `incorrect`. После третьей математической ошибки сервер возвращает проверенный разбор текущего примера и предлагает помощь взрослого или паузу. Разбор не открывает следующую задачу, не завершает часть и не выдаёт mastery. `invalid_input`, помощь и технический повтор в этот счётчик не входят.

## Состояния для кнопок Terra

- Показывать `Подсказка`, `Объясни иначе` и `Пауза`, когда есть незавершённый текущий вопрос.
- Показывать `Продолжить` при `state.phase === "paused"`.
- Показывать `Следующая часть` только при `state.curricular.awaiting_advance === true`.
- При `state.curricular.lesson_complete === true` блокировать ввод ответа и действия перехода.
- Считать ответ принятым только после HTTP-ответа сервера. Локально не увеличивать попытки, не менять `part_index` и не объявлять часть завершённой.
- Хранить полученные `session_id` и `part_revision`; для повторной доставки переиспользовать прежний `request_id`, а для нового действия создавать новый.
- При `replayed: true` применять возвращённый результат один раз по `request_id`. При `stale_part` перечитать серверное состояние и не отправлять старый текст как новую попытку автоматически.

Скрытие кнопки помогает ребёнку, но не является проверкой доступа: сервер повторно проверяет фазу и сохранённую сессию.

## Ошибки переходов

Ошибки состояния возвращаются как HTTP `409`:

| `detail.code` | Значение |
|---|---|
| `no_active_learning` | Пауза запрошена вне активного занятия. |
| `already_paused` | Повторное явное действие `pause`. |
| `not_paused` | `resume` запрошен без паузы. |
| `resume_required` | Во время паузы отправлено действие, отличное от `resume`; состояние не меняется. |
| `action_not_available_in_current_phase` | Действие не подходит текущей legacy-фазе. |
| `curricular_session_not_started` | Curricular-действие отправлено до `start`. |
| `lesson_session_mismatch` | `lesson_id` или `content_version` не совпадает с серверной сессией. |
| `current_part_not_complete` | `advance` запрошен до правильного ответа или ручного решения сервера. |
| `part_already_complete` | Повторная помощь или ответ запрошены для завершённой ordered-части, ожидающей `advance`. |
| `request_id_conflict` | Этот ID уже использован в занятии с другим содержимым. Состояние не меняется. |
| `request_replay_unavailable` | Запись повтора повреждена; клиент не должен создавать новый ID для автоматического повтора ответа. |
| `stale_session` | Запрос относится к прежнему занятию; ответ содержит текущий `session_id`. |
| `stale_part` | Новый запрос относится к прежней части; ответ содержит текущий `part_revision`. |

Неизвестное значение `action`, пустой/слишком длинный `request_id` или `session_id` возвращают HTTP `422`. Неизвестный или не допущенный урок также возвращает `422` с кодом curricular-runtime. Эти ответы не должны менять сохранённую попытку.

## Передача хранения Terra/S1a

Одна атомарная запись должна сохранять: `user_id`, `session_id`, `request_id`, отпечаток содержимого, `lesson_id`, `content_version`, `part_index`, `part_revision`, `attempts`, `incorrect_attempts`, флаги завершения и снимок ответа. Текущий JSON-журнал хранит последние 64 результата и обеспечивает семантику повторов в одном процессе. Он не гарантирует атомарность между процессами или при падении между учебным изменением и записью журнала; это граница S1a. При переносе в SQLite названия публичных полей и правила повторов не менять.

## Совместимость

Legacy-клиент может не передавать новые поля: обычное сообщение продолжает прежний сценарий. Текстовое «стоп» по-прежнему ставит активное занятие на паузу. Первое обычное сообщение после паузы только возобновляет сохранённую фазу и не оценивается. Переключение из curricular в `mode=kungfu` или `mode=homework` восстанавливает прежний legacy-контекст и также не оценивает сообщение переключения. Гарантия дедупликации действует только для запросов с `request_id`; новый UI Terra должен отправлять все три поля B2b.
