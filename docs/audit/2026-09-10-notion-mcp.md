# Проверка Notion MCP после перезапуска Codex

Дата: 2026-09-10. Цель — проверить возможность использовать Notion AI как основных исполнителей проекта.

## Подтверждено

- В конфигурации Codex включён `notion-remote`, endpoint `https://mcp.notion.com/mcp`.
- Штатный `mcpServerStatus/list` через отдельный Codex App Server возвращает `authStatus: oAuth`, сервер **Notion MCP 1.2.0** и **42 инструмента**. Новые задачи и модельные ходы для проверки не создавались.
- В каталоге есть `notion-fetch`, `notion-search-agents`, `notion-spawn-session`, `notion-send-message-to-session`, `notion-get-session-status`, `notion-wait-session`, `notion-query-sessions`, `notion-list-session-events`, `notion-read-session-event` и `notion-stop-session`.
- `notion-search-agents` поддерживает `scope: workspace` и `scope: favorites`; для перечисления без query нужно следовать nextCursor. Отдельного `notion-list-agents` в фактическом каталоге нет.
- Старый локальный сервер 2.5.1 остаётся отдельным подключением; ранее у него подтверждены 24 инструмента без вызова агентов.

## Что ещё не подтверждено

- В перечне инструментов текущей модельной беседы удалённый Notion не появился даже после перезапуска. Доступность инструментов в служебном каталоге не равна возможности вызвать их из этой беседы.
- Вызов через отдельный App Server требует загруженного контекста задачи. Текущая задача уже занята своим процессом (`already has an active writer`); её блокировка не снималась и новый контекст задачи не создавался.
- Прямая read-only проверка MCP с сохранённой OAuth-записью остановилась на initialize: HTTP 403 от Cloudflare, причина — «The site owner has blocked access based on your browser's signature». Это отказ диагностическому HTTP-клиенту; он не доказывает отсутствие подписки или прав на AI в Notion. После установления причины этот способ не обходился.
- Поэтому `notion-fetch` с id `self` и фактическое перечисление агентов ещё не выполнены. Тариф, разрешения Custom Agents, названия агентов и используемые ими модели не установлены. AI-задания не запускались.

## Следующая содержательная проверка

Использовать рабочий нативный MCP-клиент Codex, которому доступны вызовы Notion, сохранив текущую авторизацию:

1. `notion-fetch` с `{"id":"self"}`: прочитать только current_tool_access; персональные поля не переносить в журнал.
2. Проверить доступ к поиску и сессиям агентов. Наличие команд само по себе не подтверждает права тарифа.
3. `notion-search-agents` с `{"scope":"workspace","limit":100}`; пройти все страницы. При необходимости отдельно проверить favorites.
4. Сопоставить реальных агентов с карточками оркестрации. Для назначения основных исполнителей проверить их способность получать материалы и возвращать проверяемый результат.

Повторное редактирование endpoint или повторный OAuth-вход без выявленной ошибки авторизации пока не обоснованы. Нужен рабочий путь вызова инструментов, а не очередное подтверждение наличия записи в конфигурации.

Документация: [Notion MCP tools](https://developers.notion.com/guides/mcp/mcp-supported-tools), [Codex App Server](https://learn.chatgpt.com/docs/app-server).

Изменены только документы проекта. Настройки MCP, секреты, страницы Notion и пользовательские состояния не менялись.
