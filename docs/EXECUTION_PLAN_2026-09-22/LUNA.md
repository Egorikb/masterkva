# GPT-5.6 Luna — подготовка, проверки и память

Режим **medium**; оформление готовых результатов — **low**. Luna получает конкретные файлы и ожидаемый результат. Не делать её единственным арбитром учебной правильности, авторизации или транзакций. Общие правила: [README](README.md).

## D2

**Результат:** небольшой manifest принятого пакета C0 для Sol.

**Вход:** отчёт GPT-5.5 по C0, только перечисленные уроки, `lesson_runtime_map.json`, registry/contracts. **Запись:** manifest пакета рядом с учебными данными и `docs/audit/pilot-content-manifest.md`; без изменения runtime.

Проверить уникальность lesson_id/version, ссылки на реальные задания/источники/части/визуалы, разделение обучающих и контрольных вопросов. Таблица: lesson_id → version → источник → topic/skill/family → assessment → visual → статус смыслового подтверждения. Отсутствующий skill или сомнительную связь вынести Sol, не придумывать ради заполненной таблицы.

**Приёмка:** все ID существуют; нет потерянных частей и дублей; mapped/review_required/unmapped отражают принятые решения. Проверить только затронутые валидаторы. Manifest не является разрешением включить урок: допуск делает B3 после смысловой проверки.

## R1

**Результат:** один воспроизводимый путь установки, запуска и проверки текущего приложения.

**Пути:** README или `docs/RUNBOOK.md`, существующие requirements/package-lock, небольшой скрипт команд при необходимости. Пользоваться имеющимся pytest и npm scripts, не строить новый тестовый фреймворк.

На чистом временном окружении проверить объявленные зависимости, версии runtime и запуск backend/frontend с синтетической БД. Записать команды, адреса, необходимые настройки без секретов и способ сброса только тестовых данных. Известное зависание TestClient в песочнице не лечить исключением тестов: ограниченный timeout, вывод причины, штатный прогон вне этой изоляции либо полноценный HTTP-сценарий через сервер.

**Приёмка:** человек выполняет команды и получает работающий урок; ошибки зависимости имеют точную причину. Полный backend + frontend typecheck/lint/build; данные проверяются валидаторами. Не обновлять все библиотеки только из-за deprecation warning.

## Q1

**Результат:** `docs/audit/pilot-acceptance.md` с ожидаемым/фактическим поведением и версией кода.

**Вход:** [ACCEPTANCE](ACCEPTANCE.md), переданные API-контракты и принятые карточки. **Запись:** отчёт и недостающие сценарии тестов; дефекты production-кода возвращать его владельцу.

Проверить настоящий путь браузер → API → сохранение: верный/неверный ответ, 0, дроби/единицы в соответствующих заданиях, ordered, rubric, подсказка, переформулировка, пауза, повтор HTTP, одновременный запрос, перезапуск, два профиля, голосовая ошибка, отмена и отказ API. Для каждого — setup на синтетических данных, ожидаемый результат, команда/скриншот, факт, ограничение. Если форма задания ещё не допущена, тест её запрета не выдавать за функциональную поддержку.

**Приёмка:** нет открытых блокирующих дефектов на заявленном объёме; из отчёта видно, что реально работает и что закрыто. Число тестов само по себе не критерий готовности.

## Q2

**Результат:** компактный `docs/audit/astra-handoff.md` для единственной итоговой проверки.

**Вход:** Q1, текущие SHA/diff, карточки и известные ограничения. **Запись:** только этот отчёт, WORKLOG и очередь.

Объём основной записки — ориентир до 1–2 страниц: что входит в пилот; принятый base и candidate SHA; затронутые узлы; ссылки на конкретные тесты/сценарии; результаты; открытые источники; до трёх спорных вопросов. Полные логи, архивы и содержимое профилей не копировать. Ссылки на исходники обязательны: краткая записка не заменяет их независимое чтение.

**Приёмка:** Astra может проверить поставленные вопросы без повторного поиска структуры проекта. Если спорных вопросов нет, это обычная проверка кандидата, а не повод изобретать новую архитектуру.

## G1 / GN

**Результат:** матрица фактической готовности одного класса после C3/C2 и B4.

Строки — темы и задания; столбцы — источник, предметная проверка, решение/рубрика, runtime, визуал, состояние/прогресс, независимая проверка, педагог. Сводить из доказательств, не по наличию файлов. Для 1 класса учесть все 26 тем и 78 исходных заданий; дополнения считать отдельно. Для 2–9 сначала снять фактический инвентарь выбранного класса.

**Приёмка:** каждая незакрытая ячейка имеет причину и владельца, а завершённый класс соответствует ACCEPTANCE. Дефицит вариантов для повторных занятий фиксируется как дефицит, даже если все исходные упражнения подключены.
