# GPT-5.6 Terra — основная разработка продукта

Режим: **medium** для UI/отчётов, **high** для хранения и идентичности. Одна карточка за запуск. Общие правила — [README](README.md). Не редактировать API одновременно с Sol.

## U1a

**Результат:** из интерфейса можно начать и пройти настоящий B1-урок текстом.

**Вход:** приёмка B1 и контракт B2a, если уже принят. **Пути:** `frontend/components/chat-interface.tsx`, `frontend/lib/api/panda-client.ts`, `frontend/contracts/panda.ts`, экран `frontend/app/dashboard/session/page.tsx`, минимальные стили и UI-тесты.

Сохранить Next.js и существующие компоненты. Явно выбрать предмет/доступный блок; пока разрешён один урок — показывать именно его. Один вопрос, поле ответа, крупные кнопки ответа и подсказки, ожидающее состояние запроса и понятная ошибка. `mode=curricular` не должен незаметно становиться `kungfu`; клиент не отправляет правильный ответ и не считает прогресс самостоятельно. Предусмотреть возврат к прежнему занятию. Новые B2-действия включать только по принятому контракту.

**Приёмка:** настоящий локальный HTTP с синтетическим ребёнком: старт → 12 → подсказка → 13 → завершение без mastery; возврат не теряет legacy. Проверить 390×844 и планшет; typecheck/lint, целевой браузерный сценарий. Отсутствие сервера показать как ошибку, не заменять fake-успехом.

**Граница:** без полного редизайна, голоса, авторизации и новых заданий. До S1b этот экран остаётся локальным разработческим входом.

## S1a

**Результат:** шаг занятия и попытка сохраняются атомарно и переживают перезапуск.

**Зависит:** B2b. **Пути:** `backend/deeptutor/services/state_storage.py`, `student_profile_store.py`, узкие точки записи `plugins_api.py`, миграционный скрипт, тесты. Текущий JSON использует атомарную замену файла; это не равняется транзакции «проверить → записать попытку → обновить шаг» между процессами.

Использовать SQLite из стандартной библиотеки для одного сервера пилота. Хранить профиль, сессию, версию материала, текущую часть, ответ/результат/тип помощи и идентификатор повторного запроса. Уникальность запроса и изменение шага — одна транзакция; одинаковый ID с другим payload — конфликт. Проверку ответа выполнять по зафиксированной версии; несовместимость версии не решать повторной оценкой по новому эталону.

Сохранить согласованный B2-контракт; провести миграцию только синтетических JSON, с dry-run и резервной копией. Не переносить реальные состояния в этом задании. Не добавлять Postgres, очередь сообщений или универсальный ORM ради одного сервера.

**Приёмка:** два процесса/запроса одновременно отвечают одним ID — одна попытка; перезапуск возвращает тот же шаг; ошибка транзакции не оставляет половину перехода; разные дети не смешиваются; повтор по старой версии не меняет оценку; миграция и откат на синтетических данных воспроизводимы.

**Передача:** схема/версия БД, путь настройки без секретов, команды восстановления, границы гарантий. Следом S1b. Если атомарность не удаётся доказать, передать Sol конкретное воспроизведение.

## S1b

**Результат:** у родителя и ребёнка реальные серверные профили; запрос с чужим ID не открывает чужое занятие.

**Вход:** S1a; существующий `frontend/lib/auth-store.ts` сейчас моделирует login и создаёт демонстрационный прогресс. **Пути:** backend auth/profile endpoints, серверная сессия, `auth-store.ts`, login/signup и клиент API, тесты доступа.

Выбрать один минимальный способ входа взрослого для закрытого пилота и описать его. Не имитировать успешный вход любым паролем; не реализовывать собственную криптографию. Связывать сессию взрослого с принадлежащими ему профилями детей на сервере. Ребёнок выбирает свой профиль без взрослого пароля в каждом задании. Проверять доступ к chat/истории/отчёту и голосовым endpoint; произвольный `user_id` из тела не является авторизацией. Удалить демонстрационные числа там, где UI заявляет реальный прогресс.

Предусмотреть выход и отзыв сессии, очистку локального состояния при смене семьи, удаление тестового профиля и связанных записей по явному действию взрослого. Использовать существующий безопасный механизм или поддерживаемую библиотеку, выбранную по реальному стеку.

**Приёмка:** два взрослых, по два синтетических ребёнка; подмена ID/запрос без сессии/доступ после выхода отвергаются; смена семьи не показывает прошлый чат; статистика нового профиля нулевая. Независимая проверка доступа у Sol по готовому diff, без повторного проектирования всего приложения.

**Граница:** платежи, социальные логины и сложная ролевая система не нужны. Публичный многопользовательский запуск запрещён по критериям приёмки, пока эта карточка не принята.

## U1b

**Результат:** учебная сцена понятна ребёнку и соответствует текущей части.

**Зависит:** U1a, B3. **Пути:** компоненты занятия, `interactive-blackboard.tsx`, минимальные visual-компоненты, стили, UI-проверки. Сначала проверить существующие визуальные шаблоны; не заменять их несвязанной картинкой.

Показывать одну часть, крупные цели нажатия, читаемый текст, клавиатурную навигацию и видимый фокус. Панда не закрывает задачу. Предметы/группы/числовая прямая отражают текущие данные; отсутствие сцены даёт корректный текстовый вариант. Пользовательские действия на доске проходят серверную оценку по контракту. Для ordered — следующая часть только после сервера; для rubric — понятное «нужна проверка взрослого» и рабочая передача взрослому, если пакет её требует. Ноль не теряется как пустое значение.

**Приёмка:** 390×844, ширины 768 и 1024; ответ 0, несколько частей, рисунок/rubric, помощь, пауза/возврат, ошибки сети. Скриншоты и браузерный smoke; отдельно отметить, что удобство реальному ребёнку проверяет H1.

## U1c

**Результат:** ребёнок говорит и слышит преподавателя, сохраняя управление.

**Зависит:** U1b и API V1b. **Пути:** `frontend/components/voice-input.tsx`, чат/аудио UI, клиент голосового API, браузерные проверки.

Записать → показать распознанное → исправить/подтвердить → отправить как ответ с новым ID. Голосовая ошибка не уменьшает учебный результат. Озвучку можно остановить и повторить; пауза/смена урока/новая реплика отменяет старую озвучку и игнорирует поздний ответ. При отказе микрофона, STT/TTS или сети доступен текст. Настроить короткие занятия с перерывом; 3 часа из сметы не превращать в обязательную непрерывную сессию.

**Приёмка:** реальное устройство с микрофоном для живого smoke; отказ разрешения, тишина, исправление транскрипта, повтор нажатия, отмена и запоздалая озвучка. В автоматических тестах использовать заглушки провайдера, не платные вызовы.

## P1

**Результат:** отчёт родителю описывает реальные самостоятельные и подсказанные попытки.

**Пути:** `backend/deeptutor/services/progress_analytics.py`, `report_service.py`, endpoint отчёта, `frontend/app/dashboard/parent/page.tsx`, связанные графики и тесты.

Считать по S1: начатые/завершённые уроки, ошибки, помощь, ручную проверку, навыки с подтверждением и ещё не проверенные. Пустая история показывает пустое состояние, не демонстрационные достижения. Отделить время занятия от времени речи; расходы показывать только при наличии измерения V1b, с валютой и датой тарифа. Удаление профиля должно отражаться в отчёте.

**Приёмка:** синтетический набор с известным результатом сверяется вручную; два ребёнка изолированы; одна подсказанная попытка не выглядит самостоятельной; rubric не выглядит освоением. Отчёт не обещает «точную страницу потери понимания».

## R2

**Результат:** выбранный релизный кандидат можно запустить, обновить и восстановить.

**Зависит:** итоговая проверка A1 или зафиксированная независимая замена. **Пути:** runbook/конфигурация запуска/backup, CI при наличии потребности; без переписывания бизнес-логики.

Подготовить минимальный запуск на существующем хосте: Next.js + FastAPI + SQLite, переменные без секретов, доступ только к серверным ключам, ограниченные CORS/origins и ограничения запросов. Если будет сетевой доступ семей — защищённое соединение и принятая S1b. Описать миграцию, backup/restore, rollback и проверку работоспособности. Не переносить данные детей автоматически. Бэкап проверять реальным восстановлением синтетической БД.

**Приёмка:** чистый запуск по инструкции, отсутствие ключей в клиентской сборке/логах, отказ внешнего API не ломает текстовый урок, перезапуск сохраняет место, восстановление возвращает известные попытки. Реальный хост/домен/бюджет, если ещё не заданы, запросить после готового локального кандидата. Карточку можно закончить как «локальный кандидат готов, внешнее развёртывание ожидает параметры»; это не отметка о публикации.
