| [GPT-5.4](GPT_5_4.md) | medium/high, если доступны | Резерв для одного задания Terra или независимого чтения | Не запускать дополнительно к уже работающему владельцу |

## Как экономить лимиты

Расход зависит от модели, сложности задачи и объёма контекста; «одно сообщение» не является фиксированной единицей. Длинные сессии и большие проекты расходуют больше. OpenAI рекомендует ограничивать исходные материалы, ненужные MCP и выбирать меньшую модель для рутинной работы. Это согласуется с нашим порядком: короткая карточка → подходящий исполнитель → проверяемый результат. [Официальные условия](https://learn.chatgpt.com/docs/pricing).

Практические правила проекта:

1. Новую карточку открывать отдельной задачей с нужной моделью; передавать путь к ТЗ и актуальный SHA, а не всю историю этой беседы. Для одного незаконченного дефекта продолжать существующую задачу.
2. Одна карточка — один результат. Не просить «изучи всё», «доведи до идеала» или одновременно UI, базу и все учебники.
3. Начинать с указанного reasoning. High нужен в отмеченных задачах; max/ultra не включать автоматически. Настройки самостоятельно не переключаются этим планом.
4. По умолчанию один исполнитель, без подагентов. Две независимые задачи можно запускать в разных рабочих копиях после разделения файлов. Делегирование само по себе экономию не гарантирует.
5. Не поручать Astra запуск тестов, push, журнал, типовые UI-правки и повторную инвентаризацию. Получает только пакет Q2 и нужные исходники.
6. После двух безрезультатных исправлений **одного дефекта** сохранить воспроизведение и передать владельцу сложной логики; не оплачивать бесконечные повторные аудиты.
7. Проверять затронутый сценарий после изменения, полный набор — на стыке этапов. Повторять успешный прогон, когда изменился код/среда или осталось конкретное сомнение.
8. Не подключать новые MCP, платные модели, генерацию картинок и отдельную систему агентов ради выполнения этих карточек. Использовать существующие инструменты проекта.

Режимы моделей и экономный выбор reasoning согласуются с [официальным руководством по моделям](https://learn.chatgpt.com/docs/models). Точных процентов экономии и гарантированного срока в лимитах Plus этот план не обещает.

## Общие условия для всех исполнителей

- Перед работой: AGENTS.md, MEMORY.md, текущая запись WORKLOG и собственная карточка. Проверить `git status --short` и HEAD; не менять ветку поверх чужих изменений. База следующей работы должна содержать принятые исправления B1. Не предполагать, что они уже в main.
- Существующий код и библиотеки использовать первыми. Новую инфраструктуру добавлять только для требования карточки; не переписывать весь DeepTutor или весь frontend.
- Сервер определяет оценку, идентичность, прогресс и переходы. LLM объясняет. Нельзя расширять allowlist или повышать mastery ради зелёного теста.
- `backend/data/user_states.json`, ключи и личные `.env` не читать и не переносить в отчёты. Разработка/миграция только на синтетических данных. Реальный перенос — отдельная операция после проверенного восстановления.
- Общие API-файлы редактирует один владелец. WORKLOG/QUEUE обновлять последовательно при передаче; в параллельных копиях отчёты сводить при интеграции.
- Карточка закончена после работающего изменения и её приёмки. Частично выполненную помечать PARTIAL с остатком. Зависший/пропущенный тест не считать успешным.
- В конце сохранить короткую запись: ID, SHA или незакоммиченный diff, результат, проверки, ограничения, следующий ID. Новые маленькие отчёты хранить в `docs/audit/`, не создавать отдельную систему памяти.
- Commit допустим только со своими проверенными файлами. Существующие правила публикации сохраняются; этот план не является командой на автоматическое слияние, публичное развёртывание или платные вызовы.

Старые крупные карточки [ORCHESTRATION.md](../ORCHESTRATION.md) остаются картой ответственности. Эта папка уточняет размер и последовательность их исполнения; фактические результаты живут в WORKLOG.
