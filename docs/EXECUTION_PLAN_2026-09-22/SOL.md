# GPT-5.6 Sol — учебная логика и голос

Режим: **high**. Выполнять только выбранную карточку. Общие ограничения и шаблон задания — [README](README.md); порядок — [QUEUE](QUEUE.md). После каждой карточки — WORKLOG, её статус и короткая передача. Не запускать подагентов автоматически.

## B2a

**Результат:** ребёнок отвечает, просит помощь и ставит занятие на паузу разными действиями; служебное действие никогда не становится математической ошибкой.

**Вход:** принятый B1, `docs/audit/2026-09-13-b1-acceptance.md`, `ChatRequest`, текущие handlers curricular и legacy, frontend-контракт.

**Пути:** `backend/deeptutor/api/routers/plugins_api.py`, необходимые функции `practice_engine.py`/`remediation_engine.py`, `frontend/contracts/panda.ts`, затронутые API-тесты. Backend-пути сервисов здесь и ниже относительно `backend/deeptutor/services/`.

**Сделать:**

1. Зафиксировать и реализовать семантику `answer`, `hint`, `rephrase`, `pause`, `resume`, `advance`; сохранить B1 `start`. Переходы определяет сервер. Учесть текущую фазу, неверное действие и уже завершённую часть.
2. `hint/rephrase` не увеличивают число ошибок и не раскрывают следующий ответ. Переформулировка сохраняет числа и математический смысл; при недоступном LLM достаточно проверенного детерминированного текста.
3. Явная пауза сохраняет текущую часть. Возврат не оценивает сообщение возврата. Сохранить совместимость с текстовым «стоп» и текущим legacy-клиентом.
4. Записать небольшой `docs/api/panda-actions.md`: поля, допустимые действия/фазы, ошибки, примеры. Передать Terra для кнопок; детские ответы не содержат служебных эталонов.

**Приёмка:** реальный HTTP на синтетическом профиле: answer изменяет попытку; hint/rephrase/pause/resume — нет; пауза/возврат сохраняют lesson/version/part; недопустимое действие не портит состояние; переключение legacy сохраняет прежний контекст. Целевые тесты B1, Panda-контракта и новых переходов; typecheck после смены TS-схемы.

**Граница:** не добавлять SQLite, голос, новые уроки, новый UI. Не менять значения skill/topic ради простоты.

## B2b

**Результат:** повтор доставки ответа учитывается один раз; ребёнок не остаётся в бесконечном цикле ошибок.

**Вход/путь:** B2a и тот же API, curricular runtime, remediation и их тесты; контракт `docs/api/panda-actions.md`.

**Сделать:**

- Ввести идентификатор запроса/попытки с областью ребёнок + занятие, а также способ обнаружить ответ на устаревшую часть. Сохранить lesson_id/version и серверный номер части. Названия полей зафиксировать один раз для UI и S1.
- Повтор того же ID и содержимого возвращает прежний результат без второй попытки. Тот же ID с другим содержимым отвергается. Одинаковый текст с новым ID является новой попыткой, если часть ещё активна.
- Обрабатывать повтор start/advance и запоздалый ответ; не создавать второе занятие и не перепрыгивать часть. Краткий журнал в существующем хранилище — допустимый промежуточный этап; обязательную транзакционную гарантию передать S1a.
- После трёх неверных математических попыток предложить конкретный проверенный разбор, более простой шаг из разрешённого набора или помощь взрослого/паузу. Никакого произвольного задания из чужой темы. Помощь не превращает результат в самостоятельное mastery.
- Сохранить числовые исправления: дроби, десятичные числа, ноль и единицы. Неразобранный/пустой ответ отличать от неверной математики.

**Приёмка:** повторы HTTP, конфликт ID, старый номер части, новый ID с тем же текстом, серия трёх ошибок и выход/возврат, отсутствие утечки следующего ответа и mastery. Приёмка B2b проверяет семантику; конкуренцию процессов и перезапуск закрывает S1a.

**Передача:** Terra получает контракт идемпотентности и список атомарно сохраняемых полей. Не выдумывать второй контракт при переходе на SQLite.

## B3

**Результат:** небольшой законченный учебный маршрут на проверенных материалах C0, а не одиночный пример.

**Зависимости:** S1b, C0, D2. Сначала прочитать manifest и спорные связи, подтвердить каждую допускаемую строку по содержанию.

**Пути:** `curricular_lesson_runtime.py`, `curriculum_graph.py`, `skill_runtime.py`, `mastery_evaluator.py`, `diagnostic_engine.py`, `practice_engine.py`, API, только перечисленные записи registry/contracts/map/manifest, тесты. Правки по одному навыку за реализацию; большой пакет разбить на B3/<skill>.

**Сделать:** связать входную пробу → нужную предпосылку → наглядное объяснение → самостоятельный вопрос → повторную проверку. Выдавать только принятые версии заданий; точное соответствие topic/family. Если общего skill недостаточно для разных умений, явно разделить/уточнить контракт с миграцией синтетического состояния, не зачесть соседнее умение автоматически.

Mastery выдавать по согласованному правилу независимых контрольных попыток и переноса; не за один пример, не за подсказанное решение, не за rubric. Нет допустимого следующего урока — честное завершение доступного блока с возможностью вернуться. Неподтверждённые уроки остаются закрыты.

**Приёмка:** HTTP-сценарий цепочки; смешение тем/семейств исключено; обучающий ответ не подменяет контрольный; версия и результаты сохраняются через S1; слабое соседнее умение не становится освоенным. Rubric остаётся needs_review до отдельной оценки взрослым. Передать U1b реальные формы предъявления и API review, если они включены.

**Пути:** `teacher_llm.py`, `teacher_contract.py`, `config.py`, `learning_rag.py` только при реальной необходимости, точка curricular-вызова в API, тесты. Не переписывать уже существующую проверку TeacherResponse.

**Сделать:** передавать модели минимальный контекст текущего разрешённого урока/части, действие ребёнка и разрешённую помощь. Не давать модели управлять оценкой/переходом. Валидировать структуру, отсутствие преждевременного ответа и чужой темы; timeout/невалидный ответ/ошибка сети возвращают понятный fallback. Проверить привязку существующего teacher-сервиса к новому curricular-маршруту, а не наличие модуля на диске.

Для выбора провайдера взять **не более двух** доступных API-кандидатов из Qwen/DeepSeek либо уже настроенного провайдера. Сначала проверить точный model ID, доступ и текущие тарифы по документации провайдера. Фиксированная обезличенная выборка: корректные/неверные ответы, просьба выдать решение, объяснение другими словами, ошибочная речь, отказ сервиса. Выбор определяется фактическим качеством и расходами; названия из прежней таблицы не гарантия доступного API.

**Приёмка:** локальные fake-клиенты покрывают контракт, timeout, отмену, невалидный JSON, утечку ответа, неверную тему. Живой эксперимент — отдельный ограниченный прогон после настройки реального доступа и согласованного потолка расходов. Если доступа нет, сдать готовую интеграцию, отметить живую проверку как OPEN.

## V1b

**Результат:** сервер распознаёт голос и озвучивает ответ, поддерживает отмену и измеряет расход.

**Зависит:** V1a. **Пути:** небольшие STT/TTS-адаптеры в `backend/deeptutor/services/`, соответствующие API endpoints и тесты; `docs/api/voice.md`. Frontend меняет Terra в U1c.

**Сделать:** выбрать один доступный STT/TTS-провайдер после проверки русского языка, формата и текущей цены. Распознавание отдельно от `answer`: сомнительная запись и ошибка STT не становятся математической ошибкой. API возвращает транскрипт для подтверждения/исправления. Озвучка, timeout, отмена и запоздалый ответ привязаны к актуальной сессии; платные вызовы и их лимиты остаются серверными.

Считать входные/выходные токены, тарифицируемую речь/символы, повторы, ошибки и длительность ожидания. Сделать серверный потолок расходов с переходом на текст при исчерпании; значение выбирает владелец по измерениям, не зашивать прежние 700 ₽.

**Приёмка:** тишина, запрет микрофона на стороне клиента по контракту, неверный формат, отказ провайдера, повтор/отмена и поздний результат не двигают учебный шаг. Unit/API на заглушках + короткая живая проверка в согласованном бюджете. Смета 21 час в неделю вычисляется по измеренной доле речи и тарифам с датой, включая повторы; 21 час занятия не равен 21 часу STT и 21 часу TTS.

**Граница:** не добавлять второго голосового провайдера «на будущее»; не хранить сырой детский звук по умолчанию.
